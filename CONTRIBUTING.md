# Contributing

These are personal repositories, maintained by one person plus a few automation bots. Outside PRs are welcome; review may be slow, and there is no support SLA.

## Workflow

- Branch off `master` (lowercase). Do not use `main` or `Master`.
- One pull request per change, targeted at `master`.
- Fill in the pull request template. Link an issue with `Closes #N` when there is one.

## Labels

Each issue or PR should have one type label and one priority label.

- Type: `bug`, `feat`, `docs`, `refactor`, `tooling`, `test`, `assets`. Use `question` when more information is needed.
- Priority: `P1` (high), `P2` (medium), `P3` (low).

A few repos also have extras, used only where they already mean something: `area:formality` on register-study, and `governance` and `automerge` on hotel-kline-game.

There are no status labels. Close a duplicate, invalid, or won't-fix issue with GitHub's close reasons (Duplicate or Not planned). If work is blocked, write `blocked by #N` in the issue instead of adding a label.

The canonical list is [`labels.yml`](labels.yml) in this repository.
